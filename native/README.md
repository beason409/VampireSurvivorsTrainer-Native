# 2.0.0 原生版

原生 Win32 界面和游戏后端采用单 EXE 结构。提供 9 项常用功能和 23 项本局属性，共 32 个独立开关。右上角可切换简体中文和 English。指定奖励页按需加载物品图标。已有旧插件可使用手头的 1.0.0 卸载。

常用功能按卡片排列，以颜色区分选中页签和已开启的功能。指定奖励列表滚动停稳后先补可见行，再预读后面三行。最小化窗口时暂停状态区重绘及图标补载，快捷键在游戏连接且有可用绑定时才轮询。

「常用功能 → 游戏加速」把单人关卡的整体速度设为 1～10 倍，默认 4 倍。开启后可直接改倍率，关闭后恢复游戏自身的速度。暂停、升级选择期间仍按游戏原流程暂停。可在快捷键页自行绑定开关。

「常用功能 → 跳过宝箱动画」在普通宝箱演出到达可跳过位置时自动快进，领奖按游戏原流程进行。可在快捷键页自行绑定开关。

已用真实游戏目录检查物品图标、搜索和滚动。此前用户实测指定升级获得护盔，护甲从4升到5。自然宝箱领取、免消费自然扣款和去牙生成效果仍待专测。详见 [验证记录](../VALIDATION.md)。

2026-11-16，用户确认 native-pilot.2 的前四项生效、运行稳定，随后反馈 native-pilot.3 能连接但七项均不生效。实机复现发现，跨线程取得的时间样本可能按相反顺序处理，误触发心跳过期并清除全部开关。native-pilot.4 修复这一误判；真正的会话失效会断开客户端并允许重新连接，原有开关保持关闭。游戏验证范围见 [VALIDATION.md](../VALIDATION.md)。

用户已确认移动倍率效果正常。native-pilot.5修复开启中编辑数值不能直接应用的问题，并迁移普通属性及万能统一加成；native-pilot.6补齐其余属性、金币控制、开关快捷键和本机备份/恢复。native-pilot.7继续迁移指定奖励；开发验证与用户验收分别记录。

## 运行

分发只需 `VampireSurvivorsTrainer.Native.exe`。它内嵌固定原生后端及许可证，不需要 .NET、BepInEx、编译器或首次联网下载。首次需要后端时，由 Windows 解压并核验，再写入当前用户的私有缓存。已有缓存经过核对后直接复用。

1. 先正常退出游戏，在原修改器中卸载旧配套插件，再关闭旧修改器。
2. 分别打开受支持的 Steam 游戏和原生版，顺序不限。修改器在后台检测并自动连接。需要指定安装位置时，在「手动连接」中选取包含 `VampireSurvivors.exe` 的目录。点击「自动连接」可回到自动模式。
3. 进入普通单人关卡，在“常用功能”或“本局属性”页选择目标值和开关。已开启的数值输入停顿约300毫秒后自动应用，失焦或按Enter立即提交，无需重新开关。输入未完成或越界时保留上次有效值。
4. 关闭持续功能后，后续事件使用游戏当前的正常计算；本局已经获得的经验和等级照常保留。关闭窗口、断连、关卡结束、换角色或主线程观察失效会清除对应持续修改。已保存的永久金币不会因关闭开关而回退。DLL 保留至游戏退出。若提示旧后端，需要重启游戏后再连接。

| 功能 | 范围与作用 |
| --- | --- |
| 护甲 | 绝对值 0–10000，默认20；关闭后回到当前正常值，保留期间的正常升级。 |
| 生命不减 | 仅将本地角色的正、有限受伤参数改为0，继续执行游戏原有受伤流程。 |
| 经验倍率 | 倍率1–1000，界面预设2；处理本地角色实际获得的经验。 |
| 伤害倍率 | 倍率1–1000，界面预设2；处理本地角色当前持有武器（含隐藏武器）造成的正、有限伤害，环境和未知来源保持原样。 |
| 移动倍率 | 倍率0.25–10，界面预设2；只处理当前本地角色已核验的移动速度返回值。 |
| 快速冷却 | 将当前持有、已核验基础武器的正、有限开火间隔限制为至多100毫秒；开启/关闭时通过游戏原有方法刷新其开火计时。 |
| 一击必杀 | 对本地持有武器造成的正、有限普通敌人命中，先计算伤害倍率，再至少送入当前生命值100倍的有限伤害；死亡与奖励继续由游戏结算。 |
| 金币消费不减 | 需要有效启动前备份；只将当前本地普通钱包的正、有限扣款参数改为0，保留游戏原方法和其他参数。其他配置钱包不覆盖。 |

经验、伤害乘积超出有限浮点范围时沿用原输入。永久金币与指定奖励使用窗口按钮。

快速冷却适配的九个基础武器类型为 `WHIP`、`MAGIC_MISSILE`、`KNIFE`、`AXE`、`CROSS`、`HOLYBOOK`、`FIREBALL`、`HOLYWATER`、`LIGHTNING`，并要求当前武器的虚拟调用路线通过核验。进化、特殊或未列出的武器沿用原间隔。一击必杀排除已死亡及子弹对象，环境和未知伤害来源保持原样；极高生命值的计算饱和至有限浮点上限。

## 本局属性

属性页支持中英文、滚动、开启中改值，并显示正常值、最近基础getter实际返回及读取/修改次数。正常值来自不改变游戏的原始采样；没有实际读取时，“最近返回”保持未知。临时资源另显示当前绑定值，采样不计作实际getter读取。带武器因子或下限的Final返回仅保留在诊断中。

| 属性 | 输入范围 |
| --- | --- |
| 生命上限 | 1–1000000 HP；提高上限不补血，下调或关闭时只压低超出有效上限的生命。 |
| 护甲 | 0–10000点。 |
| 生命恢复 | 0–10000 HP/秒。 |
| 力量、攻击范围加成 | -100%–900%。 |
| 弹射速度、持续时间加成 | -100%–400%。 |
| 冷却缩减 | 0%–90%，保留游戏传入的下限。 |
| 额外发射数量 | 0–100个，整数。 |
| 移动速度加成 | -90%–1000%。 |
| 幸运、诅咒加成 | -100%–10000%。 |
| 经验成长、金币收益加成 | 0%–10000%；金币收益属性不设置永久钱包。 |
| 万能统一加成 | 0%–400%，统一覆盖力量、弹速、持续时间和范围，已单独开启的属性优先。 |
| 拾取范围 | 0–10000，使用独立临时半径，并调用游戏原方法刷新。 |
| 魅力 | 0–1000，使用独立Int临时字段绑定；与诅咒共同刷新关卡计算。 |
| 复活次数 | 0–1000，整数。 |
| 重选、跳过、排除次数 | 各0–10000，整数。 |
| 次数保留概率、去牙概率 | 各0%–100%；去牙影响后续生成的敌人。 |

加成100%表示原始乘数2，移动、经验和伤害的常用倍率继续在对应属性之后相乘。关闭后使用当前正常计算，保留正常升级。诅咒启用、改值和关闭时通过游戏原方法刷新关卡计算。

次数、拾取范围和魅力使用独立临时绑定，保留正常绑定；魅力为Int字段绑定，实机记录5→2，关闭后恢复正常100，绑定采样不计作天然getter读取。临时次数按游戏流程消耗，相同目标不会每帧重新生成或补满；更改目标会建立新的临时预算。正常升级、Set和Reset期间暂时切回正常绑定，完成后继续使用已消耗的临时预算。重选、跳过、排除已实测从10消耗到9且持续不回填，关闭后恢复正常资源。正常复活基线为0时已实际完成两次附加复活，剩余2→1→0，后续暂停观测仍为0且未回填。“封印”不在属性范围内。

## 快捷键、金币与备份

快捷键只绑定7项常用开关和23项属性开关，默认F1–F7对应常用功能，属性键初始未绑定。支持改绑、冲突提示、清除和本机保存，只在已连接游戏处于前台时生效；编辑键位和维护操作期间暂停注册。快速点按、重复与持键切回有策略回归；实机已核对F8自定义生命保护和F2默认一击必杀的开启/关闭，修改器前台按F8未触发。永久金币设值和指定奖励使用按钮，不绑定快捷键。

在「局外金币」页查看普通模式余额，输入目标金额后点击「设置并保存」。永久金币只在普通单人主菜单、没有当前角色且钱包配置匹配时设值。输入须为 0–999999999 范围内游戏 float 能精确表示的整数。游戏确认持久保存后显示结果，失败时会尝试恢复并保存原余额。免消费同时开启时，已完成三次精确设值并恢复测试前余额；免消费的自然扣款仍待专测。

金币控制需要本次游戏启动前、12小时内的有效备份。先退出游戏和Steam，在维护页选择游戏目录并创建备份，再启动游戏连接；程序不会自动关闭或启动游戏、安装旧插件。连接和金币请求核对备份与当前游戏目录、版本、文件SHA-256及非空Steam SaveData，普通恢复manifest不能替代授权proof。

备份/列表/恢复兼容旧`manifest.json`及`session-proof.json`，保留旧记录。恢复前要求游戏和Steam退出，先建立保护快照；失败尝试自动回滚。仅处理当前Steam账户及游戏已知存档位置，拒绝链接或越界路径。Steam云同步元数据保留当前内容；完整清单会移除快照之外的存档文件，早期proof-only备份仅覆盖其列出的文件。

备份使用显式配置的数据目录，未配置时使用当前用户的私有应用数据目录。界面设置和备份保存在本机，旧配置只按已知字段读取，不上传存档或安装记录。

## 指定奖励

在“指定奖励”页按中文、英文或ID搜索，选择物品后再应用目标或开启用途。仅选中列表项不会启用；主菜单可读取目录，开启需要就绪的普通单人关卡。宝箱与升级共用目标、分别开关，开启时更换目标会保留当前用途状态，关闭后的迟到改值不会重新开启。

目录来自当前游戏的已加载数据，保留基础内容和已加载DLC范围。首次加载按小步骤分片推进，界面显示加载中并自动重试，完整后再分页返回缓存；游戏语言保持不变。实机冷启动读取344项，第一页200项均有英文名；真实窗口的中文、英文和`MAGIC_MISSILE`搜索均定位到同一项。

升级指定只替换一个普通候选，仍需在游戏内选择；选择其他物品不会补发目标。实机已完成魔杖取得、已有斧头升级，以及血笞通过游戏原流程替换神鞭。候选出现与实际取得分别计数；关闭后正常升级继续进行。已满级目标明确拒绝。进化被动、卡牌、独立手选界面、金币/食物/极限突破菜单不替换。

宝箱代码通过原生奖品工厂替换至多一个合适的装备奖励，原游戏负责领取。自然宝箱领取仍待实测。关闭后，新出现的宝箱和候选恢复正常行为，已取得的物品保留。

图标从当前游戏图集读取，每次只请求一张，优先选中项和可见行。缺图时仍可搜索和选择物品。缓存只在内存中保存。接口与作用域依据见 [指定奖励接口](evidence/reward-route.md)。

## 构建与检查

```powershell
./scripts/Build-Native.ps1 -SizeOptimization
./scripts/Verify-Native.ps1 -SkipBuild
```

构建脚本固定 Zig 0.15.2，首次从官方地址下载到忽略的开发依赖目录并校验 SHA-256。生成后端 DLL，再将 LZMS 压缩数据及压缩前后两份 SHA-256 嵌入 EXE。生成物位于 `artifacts/native/release`。编译器不进入分发包。`-NoDownload` 使用已准备的编译器，`-ZigPath` 可指定同一固定版本。上述 Release 命令采用 Oz/ThinLTO，省略该开关可构建 Os 对照。

`version.json`固定原生版本，构建时同步后端协议版本、生成版本头和前端 PE 资源版本。校验脚本核对构建版本、PE版本及完整嵌入许可正文。

首轮护甲版本的同源测量：Os EXE为1,290,240字节，Oz/ThinLTO为839,680字节（820 KiB）。各轮的最终体积及检查结果见当次 `native-build.json` 和 `verification/summary.json`。单 EXE 已包含后端压缩数据，私有缓存额外占用 DLL 展开后的大小。

本轮90项原生离线测试覆盖纯策略、严格 JSON、实际 Win32 命名管道、会话和期限、主线程队列、关闭取消、真实getter与采样分离、临时资源、金币授权和备份恢复，以及指定奖励的独立用途、共享目标、实际取得记录和处理中取消。隔离备份测试覆盖旧格式、保护快照、回滚、篡改和目录联接拒绝；pilot.6曾以原生维护服务实际恢复4个文件，Steam重开后3份进度文件SHA-256仍匹配测试前基线，本轮最终恢复尚待完成。双语页面、旧加载器提示、旧原生版本提示及模拟连接预览另行检查，模拟预览不作为游戏效果证据。只有显式提供 `Verify-Native.ps1 -GameDirectory '游戏目录'` 时才额外进行只读文件指纹检查。

实机验证使用的可复用步骤见 [战斗测试计划](../tools/Trainer.Probe/plans/native-combat.json)、[移动与冷却测试计划](../tools/Trainer.Probe/plans/native-extended.json)、[实时改值与属性测试计划](../tools/Trainer.Probe/plans/native-stats.json)、[指定奖励测试计划](../tools/Trainer.Probe/plans/native-rewards.json) 和 [Probe说明](../tools/Trainer.Probe/README.md)。计划将后续触发事件与关闭恢复分开记录，实际效果以自然受击、拾取、命中、移动、开火和实际取得结果核对。

## 实现与边界

- 宿主校验包含游戏 EXE、GameAssembly 和元数据三个 SHA-256，以及 Steam App ID/Build；加载对象只来自当前 EXE 内嵌的固定后端。没有任意 PID、DLL或导出函数的加载参数。
- 管道沿用 v1 格式并限制本机用户、Session 和实际进程；能力字段只开放本试点。现有 WinForms 端仍校验原加载链，使用独立原生界面进行本阶段验证。
- 开启及目标变更进入 Unity 主线程队列，超过1.5秒未开始执行则取消；关闭单项仅关闭该项并取消其旧排队，“关闭全部属性”关闭23项属性，“关闭全部”关闭所有持续功能。已开始的金币保存事务返回真实完成或恢复结果。独立看门狗处理3秒断连，超过1秒无新鲜主线程观察也会关闭功能，恢复观察后保持关闭。实时改值省略开关字段，迟到改值不会重新开启已关闭项。
- Hook过滤当前本地角色的属性、持有武器的间隔返回值或战斗事件参数；开火计时刷新使用游戏自身方法，钱包、永久强化及存档由游戏原有流程维护。版本、入口或虚拟调用路线无法核验时，相应能力保持不可用。
- 主线程和护甲入口依据见 [护甲接口](evidence/armor-route.md)，生命、经验与伤害见 [战斗接口](evidence/combat-route.md)，移动和冷却见 [移动与冷却接口](evidence/movement-cooldown-route.md)。
- 普通属性的方法组、单位、原始采样、有效刷新及恢复依据见 [普通属性接口](evidence/ordinary-stats-route.md)。
- 临时次数、正常升级隔离、GC引用寿命及普通钱包保存依据见 [资源与钱包接口](evidence/resource-wallet-route.md)。
- 指定奖励使用核验后的封闭泛型集合及原生工厂/选择流程，方法、GC引用与嵌套作用域依据见 [指定奖励接口](evidence/reward-route.md)。目录分片不放宽1秒状态新鲜度或1.5秒请求期限；请求取消或超时后，晚返回的验证结果不会启用用途。

运行 `--licenses` 或界面的“说明与许可”查看原样嵌入的项目及第三方许可证。依赖源码与许可证固定在 `vendor/manifest.json`、`vendor/runtime-licenses.json`，编译器固定在 `toolchain.json`。

迁移总目标与全功能验收口径见 [轻量化架构](../docs/COMPACT-ARCHITECTURE.md)。
